# Глоссарий проекта FinHall

| Термин / Сокращение | Определение |
| :--- | :--- |
| **FinHall** | Название разрабатываемого веб-приложения для интернет-банкинга. |
| **SPA** | Single Page Application (одностраничное приложение) — тип веб-приложения, который загружается один раз и динамически обновляет контент без перезагрузки страницы. |
| **Backend** | Серверная часть приложения, реализованная на Java Spring Boot. |
| **Frontend** | Клиентская часть приложения, реализованная на React. |
| **JWT** | JSON Web Token — стандарт создания токенов доступа, используемых для аутентификации и обмена информацией между клиентом и сервером. |
| **2FA** | Two-Factor Authentication (двухфакторная аутентификация) — метод подтверждения входа, требующий два разных способа подтверждения (в FinHall: пароль + код по email). |
| **ACID** | Набор требований к транзакционной системе (Атомарность, Согласованность, Изолированность, Долговечность), гарантирующий целостность данных. |
| **Dashboard** | Главный экран (панель управления) приложения, отображающий баланс и основные виджеты. |
| **Транзакция** | Операция перевода денежных средств между счетами. |
| **Выписка** | Документ, содержащий историю транзакций клиента за определенный период (в FinHall экспортируется в PDF). |
| **Лимит** | Ограничение на сумму или количество операций (например, дневной лимит на переводы), устанавливаемое администратором. |
| **iText** | Библиотека на Java для генерации PDF-документов. |
| **BR** | Business Requirement (бизнес-требование). |
| **MVP** | Minimum Viable Product (минимально жизнеспособный продукт) — продукт с минимальным набором функций, достаточным для удовлетворения первых пользователей. |

# Спецификации вариантов использования (Use Cases) FinHall

## Описание актеров (Действующих лиц)

*   **Клиент (Client)** — физическое лицо, пользователь банковских услуг. Инициирует вход, просмотр баланса, переводы, конвертацию валют, анализ расходов и экспорт выписок.
*   **Администратор (Admin)** — сотрудник банка. Отвечает за настройку глобальных лимитов и управление учетными записями (блокировка/разблокировка).
*   **Сервис курсов валют (Currency API)** — **внешняя система** (например, API НБРБ), предоставляющая актуальные курсы валют.

## UC-01: Вход в систему (Authentication with 2FA)

*   **Краткое описание:** Пользователь входит в систему, используя логин (email/телефон), пароль и одноразовый код, который приходит на почту.
*   **Актеры:** Клиент, Администратор.
*   **Предусловия:** Пользователь зарегистрирован в системе.
*   **Основной поток:**
    1. Пользователь вводит логин и пароль.
    2. Система проверяет корректность пароля.
    3. Система генерирует одноразовый код и отправляет его на email пользователя.
    4. Пользователь вводит код из email.
    5. Система подтверждает код и предоставляет доступ к главному экрану (Dashboard).
*   **Альтернативный поток (A1): Неверный пароль.** Система выводит ошибку, возврат к шагу 1.
*   **Альтернативный поток (A2): Неверный 2FA-код.** Система выводит ошибку и предлагает запросить новый код, возврат к шагу 3.
*   **Постусловия:** Пользователь аутентифицирован, открыт доступ к функциям системы. Действует автологаут при неактивности >10 минут (REQ-SEC-003).

## UC-02: Просмотр баланса (View Balance)

*   **Краткое описание:** Клиент просматривает список своих счетов и актуальный баланс на главном экране (Dashboard).
*   **Актеры:** Клиент.
*   **Предусловия:** Пользователь авторизован (выполнен UC-01).
*   **Основной поток:**
    1. Пользователь открывает главный экран (Dashboard).
    2. Система отображает список счетов клиента и актуальные балансы.
*   **Постусловия:** Клиент видит актуальный баланс (время загрузки экрана ≤ 3 сек, REQ-PERF-001).

## UC-03: Перевод средств (Funds Transfer)

*   **Краткое описание:** Клиент переводит деньги между своими счетами или на счет другого клиента. При переводе проверяются ограничения по суточному лимиту и лимиту на одну операцию.
*   **Актеры:** Клиент.
*   **Предусловия:** Пользователь авторизован. У него есть счет с достаточным балансом.
*   **Основной поток:**
    1. Клиент выбирает счет списания и счет зачисления.
    2. Клиент вводит сумму перевода.
    3. Система проверяет, не превышает ли сумма перевода установленный лимит на одну операцию.
    4. Система проверяет, не превышает ли сумма перевода с учетом уже совершенных сегодня операций установленный суточный лимит.
    5. Система проверяет наличие достаточной суммы на счете списания.
    6. Система выполняет перевод: списывает средства со счета отправителя и зачисляет на счет получателя.
    7. Система сохраняет информацию о транзакции в истории операций.
    8. Система выводит сообщение об успешном переводе (время обработки ≤ 5 сек, REQ-PERF-002).
*   **Альтернативный поток (A1): Превышен лимит на одну операцию.** 
    1. На шаге 3 система обнаруживает, что сумма больше установленного лимита на одну операцию.
    2. Система выводит сообщение: «Сумма перевода превышает лимит на одну операцию».
    3. Вариант использования завершается.
*   **Альтернативный поток (A2): Превышен суточный лимит.** 
    1. На шаге 4 система обнаруживает, что суммарные операции за день превышают суточный лимит.
    2. Система выводит сообщение: «Превышен суточный лимит на переводы».
    3. Вариант использования завершается.
*   **Альтернативный поток (A3): Недостаточно средств.** 
    1. На шаге 5 система обнаруживает нехватку средств на счете.
    2. Система выводит сообщение: «Недостаточно средств на счете».
    3. Вариант использования завершается.
*   **Альтернативный поток (A4): Сбой при проведении транзакции.** 
    1. В процессе выполнения перевода (шаг 6) происходит сбой.
    2. Система отменяет все изменения (rollback, REQ-REL-001).
    3. Система выводит сообщение: «Не удалось провести платеж. Попробуйте позже».
*   **Постусловия:** Средства переведены, транзакция записана в историю, балансы обновлены, суточный счетчик переводов увеличен.

## UC-04: Конвертация валют (Currency Exchange)

*   **Краткое описание:** Клиент просматривает курсы валют и конвертирует суммы между поддерживаемыми валютами (мультивалютность).
*   **Актеры:** Клиент, Сервис курсов валют (Currency API).
*   **Предусловия:** Пользователь авторизован. Доступен внешний API курсов.
*   **Основной поток:**
    1. Клиент открывает раздел «Курсы валют».
    2. Система запрашивает актуальные курсы у внешнего Сервиса курсов валют.
    3. Система отображает курсы и калькулятор конвертации.
    4. Клиент вводит сумму и выбирает валюты.
    5. Система рассчитывает и отображает результат.
*   **Альтернативный поток (A1): Внешний API недоступен.** Система выводит последние сохраненные курсы с пометкой «Данные могут быть неактуальны».
*   **Постусловия:** Клиент получил информацию о курсах и результат конвертации.

## UC-05: Анализ расходов (Expense Analytics)

*   **Краткое описание:** Клиент просматривает графики расходов по категориям за месяц/год.
*   **Актеры:** Клиент.
*   **Предусловия:** Пользователь авторизован. Есть история транзакций.
*   **Основной поток:**
    1. Клиент открывает экран аналитики (AnalyticsScreen).
    2. Система анализирует историю транзакций клиента и группирует их по категориям.
    3. Система строит графики и отображает их.
*   **Постусловия:** Клиент видит визуализацию своих расходов.

## UC-06: Экспорт выписки в PDF (Export Statement to PDF)

*   **Краткое описание:** Клиент выгружает историю транзакций за выбранный период в виде PDF-файла.
*   **Актеры:** Клиент.
*   **Предусловия:** Пользователь авторизован. Есть транзакции за период.
*   **Основной поток:**
    1. Клиент нажимает «Экспорт в PDF» и выбирает период.
    2. Система формирует PDF-документ с таблицей транзакций.
    3. Система отправляет файл клиенту, браузер скачивает его.
*   **Альтернативный поток (A1): Нет транзакций.** Система выводит: «За выбранный период операций не найдено».
*   **Постусловия:** PDF-файл сформирован и скачан.

## UC-07: Управление лимитами (Manage Limits)

*   **Краткое описание:** Администратор устанавливает лимиты на транзакции (суточный лимит и лимит на одну операцию).
*   **Актеры:** Администратор.
*   **Предусловия:** Администратор авторизован.
*   **Основной поток:**
    1. Администратор открывает панель управления лимитами.
    2. Администратор задает суточный лимит и лимит на одну операцию.
    3. Система сохраняет новые настройки.
*   **Альтернативный поток (A1): Некорректные значения лимитов.**
    1. На шаге 2 администратор вводит отрицательное значение или значение суточного лимита меньше лимита на одну операцию.
    2. Система выводит сообщение об ошибке и предлагает скорректировать значения.
    3. Возврат к шагу 2.
*   **Постусловия:** Лимиты обновлены и применяются к новым транзакциям.

---

## UC-08: Блокировка учетной записи клиента (Block User Account)

*   **Краткое описание:** Администратор блокирует доступ клиента к системе.
*   **Актеры:** Администратор.
*   **Предусловия:** Администратор авторизован.
*   **Основной поток:**
    1. Администратор выбирает клиента в списке пользователей.
    2. Нажимает «Заблокировать».
    3. Система меняет статус учетной записи на «Заблокирована» и завершает все активные сессии этого пользователя.
*   **Постусловия:** Клиент не может войти в систему.

## UC-09: Просмотр логов (View Audit Logs)

*   **Краткое описание:** Администратор просматривает журнал критических операций (REQ-OBS-001).
*   **Актеры:** Администратор.
*   **Предусловия:** Администратор авторизован.
*   **Основной поток:**
    1. Администратор открывает «Журнал событий» и применяет фильтры.
    2. Система извлекает и отображает записи журнала.
*   **Постусловия:** Администратор ознакомлен с логами.

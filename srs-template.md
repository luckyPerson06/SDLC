## 1. Введение

### 1.1 Назначение документа

Настоящий документ (SRS) определяет требования к веб-приложению интернет-банкинга FinHall. Документ предназначен для команды разработки (backend и frontend), QA-инженеров и заинтересованных лиц со стороны банка. SRS определяет *что* должна делать система, и служит основой для проектирования, реализации и тестирования.

### 1.2 Область применения продукта

FinHall — это веб-приложение для удаленного банковского обслуживания клиентов. Продукт позволяет пользователям просматривать баланс, совершать переводы, оплачивать услуги, а также предоставляет инструменты для анализа расходов и конвертации валют. Система снижает нагрузку на физические отделения банка и повышает удержание клиентов. Приложение реализуется как SPA (Single Page Application) с REST API на базе Spring Boot.

### 1.3 Определения, акронимы и сокращения

| Term | Definition |
|------|------------|
| API | Application Programming Interface — программный интерфейс для взаимодействия компонентов |
| SPA | Single Page Application — одностраничное веб-приложение |
| 2FA | Two-Factor Authentication — двухфакторная аутентификация |
| SRS | Software Requirements Specification — спецификация требований к ПО |
| MVP | Minimum Viable Product — минимально жизнеспособный продукт |
| BR | Business Requirement — бизнес-требование |

## 2. Обзор продукта

### 2.1 Перспектива продукта

FinHall является новым продуктом банка, заменяющим устаревший личный кабинет. Система интегрируется с внешними сервисами для получения актуальных курсов валют. Бэкенд реализуется на Spring Boot, фронтенд — на базе современного JS-фреймворка (React/Vue).

### 2.2 Функции продукта

- Управление профилем и безопасный вход (2FA).
- Просмотр счетов и истории транзакций.
- Осуществление переводов и оплаты услуг.
- Просмотр актуальных курсов валют и конвертация.
- Анализ расходов (графики по категориям).
- Панель администратора для управления лимитами.

### 2.3 Ограничения продукта

- Приложение должно быть реализовано как адаптивное веб-приложение (мобильное приложение вне рамок текущего MVP).
- Бэкенд должен использовать Java Spring Boot.
- Внешние интеграции (курсы валют) осуществляются через сторонние REST API.

### 2.4 Характеристики пользователей

- **Клиент:** физическое лицо, пользователь банковских услуг. Ожидает высокого уровня безопасности, интуитивного интерфейса, быстрого доступа к балансу и операциям.
- **Администратор:** сотрудник банка, отвечающий за настройку глобальных лимитов и управление учетными записями.

### 2.5 Допущения и зависимости

- Доступность внешних API курсов валют (например, НБРБ).
- Предполагается, что пользователи имеют доступ к устройству для получения SMS-кодов (для 2FA).

## 3. Требования

### 3.1 Внешние интерфейсы

#### 3.1.1 Пользовательские интерфейсы
Веб-интерфейс должен быть адаптивным (поддерживать Desktop, Tablet, Mobile).
Основные экраны: LoginScreen, Dashboard, TransferScreen, AnalyticsScreen.

#### 3.1.2 Аппаратные интерфейсы
Не применимо (используется стандартное клиентское оборудование).

#### 3.1.3 Программные интерфейсы
- Интеграция с внешним API для получения курсов валют.
- Взаимодействие Frontend (SPA) и Backend (Spring Boot) по протоколу REST (JSON).

### 3.2 Функциональные требования

**REQ-FUNC-001: Регистрация и Вход**
- **Statement:** Система должна предоставлять возможность входа по логину (телефон/email), паролю и коду 2FA.
- **Rationale:** Обеспечение безопасности аккаунта (BR-6).
- **Verification Method:** Test.

**REQ-FUNC-002: Просмотр баланса**
- **Statement:** Система должна отображать список счетов клиента и актуальный баланс на главном экране (Dashboard).
- **Rationale:** Базовая потребность клиента (BR-1).
- **Verification Method:** Demonstration.

**REQ-FUNC-003: Перевод средств**
- **Statement:** Система должна позволять клиенту переводить средства между своими счетами и на счета других клиентов с проверкой остатка.
- **Rationale:** Снижение нагрузки на отделения (BR-1).
- **Verification Method:** Test.

**REQ-FUNC-004: Курсы валют и конвертер**
- **Statement:** Система должна загружать актуальные курсы валют и предоставлять калькулятор для конвертации сумм.
- **Rationale:** Удержание клиентов (BR-2).
- **Verification Method:** Demonstration.

**REQ-FUNC-005: Анализ расходов**
- **Statement:** Система должна строить графики расходов по категориям за месяц и год.
- **Rationale:** Конкурентное преимущество (BR-4).
- **Verification Method:** Demonstration.

**REQ-FUNC-006: Управление лимитами**
- **Statement:** Система должна позволять Администратору устанавливать глобальные лимиты на транзакции.
- **Rationale:** Безопасность (BR-7).
- **Verification Method:** Test.

### 3.3 Качество обслуживания

#### 3.3.1 Производительность
- **REQ-PERF-001:** Время загрузки экрана Дашборда не должно превышать 3 секунд (BR-11).
- **REQ-PERF-002:** Обработка запроса на перевод не должна превышать 5 секунд.

#### 3.3.2 Безопасность
- **REQ-SEC-001:** Все передаваемые данные должны быть защищены протоколом HTTPS.
- **REQ-SEC-002:** Пароли пользователей должны храниться в виде хешей (например, bcrypt).
- **REQ-SEC-003:** Автоматический разлогин при неактивности более 10 минут.

#### 3.3.3 Надёжность
- **REQ-REL-001:** При ошибке платежного шлюза транзакция должна откатываться (rollback).

#### 3.3.4 Доступность
- **REQ-AVAIL-001:** Доступность сервиса должна составлять не менее 99.5% в месяц.

#### 3.3.5 Наблюдаемость
- **REQ-OBS-001:** Все критичные операции (вход, перевод) должны логироваться с указанием ID пользователя и времени.

### 3.4 Соответствие стандартам
Архитектура и защита данных должны соответствовать базовым требованиям PCI DSS (в части обработки данных банковских карт, если применимо) и локальным стандартам банка.

### 3.5 Проектирование и реализация

#### 3.5.1 Установка
Система должна развертываться в виде Docker-контейнеров.

#### 3.5.2 Сборка и поставка
Использование CI/CD пайплайна (например, GitHub Actions) для сборки Spring Boot приложения.

#### 3.5.4 Сопровождаемость
Код должен следовать паттернам ООП и разделяться на слои (Controller, Service, Repository).

### 3.6 ИИ/МО
Не применимо для текущей версии MVP.
